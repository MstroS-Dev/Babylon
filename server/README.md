# Site Comms Server

Backend for the worker task/communication app. Tested and working: worker
registration, task creation, status flow (assigned → in_progress → done),
photo uploads, and Claude-based task review.

## Setup

```bash
python3 -m pip install -r requirements.txt
export ANTHROPIC_API_KEY=your_key_here
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Visit `http://your-server:8000/docs` for interactive API docs (auto-generated by FastAPI).

## What's implemented

- `POST /workers/register` — app worker registers with name, photo, language
- `POST /workers/whatsapp` — manager manually adds a WhatsApp-only worker (name, phone, language)
- `GET /workers` — list all workers, for the console
- `POST /tasks` — manager creates a task for a worker (title, description). WhatsApp
  workers get it server-translated and sent immediately; app workers translate
  on-device via ML Kit, so the server just stores it (push notification wiring
  is a TODO, see below)
- `GET /tasks` — list all tasks with status and photos
- `POST /tasks/{id}/photo` — upload before/after photos. Before-photo flips
  status to `in_progress`; after-photo flips it to `done` and triggers a
  Claude review comparing the photos to the task description
- `WS /ws/console` — WebSocket that broadcasts live updates (new worker
  registered, task created, task updated) — this is what your manager
  console web app connects to for real-time updates

## Still needs wiring (next steps)

1. **Push notifications to app workers.** Right now the server stores the
   task but doesn't push it to the Android app. Add Firebase Cloud
   Messaging (FCM): when the app registers, save its FCM token in
   `device_token`, then call FCM's send API in `create_task()` in `main.py`.
2. **WhatsApp credentials.** `app/whatsapp.py` runs in "dev mode" (just
   logs to console) until you set `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`,
   and `TWILIO_WHATSAPP_FROM` as environment variables. You'll need a Twilio
   account with WhatsApp Business API access.
3. **Incoming WhatsApp replies / photos.** Add a `POST /whatsapp/webhook`
   endpoint that Twilio calls when a worker replies — translate the text
   back to the manager's language and store it as a `Message`, and treat
   incoming media as before/after task photos.
4. **Auth.** There's currently no authentication on the manager endpoints —
   fine for local testing, but add an API key or login before this is
   reachable from the public internet.

## Deploying

Put this on an Oracle Cloud (or any Linux) VM, install Python 3.11+,
follow Setup above, and run it behind `systemd` + nginx (or just
`nohup uvicorn ... &` to start).
